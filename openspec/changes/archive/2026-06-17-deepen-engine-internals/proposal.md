# Deepen engine internals

## Why

A deletion-test pass over `internal/engine` found five internal seams that are shallow, leaky, or dead, all of which cost testability and navigability without buying anything:

- **Host I/O is reached two inconsistent ways.** Resolvers either take injected `commandRunner`/`fileReader` function parameters (threaded through ~55 signatures) or call `exec.Command`/`os.ReadFile` directly — 47 such direct calls in `core.go`/`virtual.go` that bypass the seam and cannot be faked in a test. The `Session` already exists as the per-run host-probe carrier (`session.go`), so the seam has a natural home it isn't using.
- **External fact loading had an implicit mode seam.** `LoadExternalFactsWithBlocklist` and the former `LoadExternalFactsFromDirs` shared most implementation but encoded CLI-vs-library behavior through a `failures == nil` sentinel (`external.go:137-190`), split environment facts between the loader and `Engine.Discover` (`engine.go:197-205`), and relied on package globals for platform/filesystem/command seams (`externalFactGOOS`, `externalFactRunCommand`, `externalFactOpen`). This is the input contract's most sensitive loader, and its semantics deserve one deep module rather than sentinel branches plus global test hooks.
- **The config file is fully re-parsed on every access.** Each of `ConfigFileOptions`, `ConfigBlocklist`, `ConfigFactGroups`, `ConfigTTLs` re-runs the whole parse (`config.go:94-184`). Two separate paths pay for it: the CLI parses 5× per run (`app.go:296,320,324,386,390`, fact-groups twice), and — independently, for library consumers that opt into a config file — `Engine.Discover` parses 4× (`engine.go:139,148,152,162`).
- **The `Formatter` seam is dead.** `Formatter`/`BuildFormatter` exist (`formatter.go:20-48`) but have no non-test caller, because `FormatOptions` carries no dotted-merge or color flag — so the CLI hand-rolls a four-branch switch over `Format*WithDottedFacts`/`FormatLegacyColored` (`app.go:402-411`).
- **A directed-graph module is dead.** `directed_graph.go` (cycle detection + topological sort, 131 lines) and its 89-line test are referenced nowhere in production — the abandoned skeleton of a fact-ordering scheme.
- **Ruby and Puppet package-version facts are stale compatibility ballast.** Facts no longer supports Ruby runtime integration, yet core discovery still shells out to `ruby` for a `ruby` structured fact and still probes puppet-agent/Puppet package versions through `aio_agent_version` and `puppetversion`. These are package/runtime inventory probes for the old stack, not Go-native facts.

Most of this change is locality and testability work, paid down before more facts land on top. The Ruby/Puppet package-version removal is an intentional output-contract amendment: Facts is Go-native, and the built-in fact surface no longer reports Ruby runtime or Puppet package versions.

## What Changes

- **Carry host I/O on the Session.** `Session.commandOutput` already exists (`core.go:2864`); make its `exec` call go through a swappable host handle on the Session and add the file sibling (`s.readFile`, `s.stat`). Route the 47 direct `exec`/`os` calls — the ones that bypass every seam and cannot be faked — through these methods, fixing concrete inconsistencies like `currentMountEntries` (takes `*Session` but calls `exec.Command`/`os.ReadFile` directly, `core.go:2437,2443,2449`). Keep the pure `parse*`/`*ForPlatform` functions exactly as they are — they take parsed input, not host handles, and remain the cross-platform unit-test surface (AGENTS.md: "Platform logic should be tested through fixtures or injected probes"). Collapsing the existing `commandRunner`/`fileReader` parameter threading (already fakeable in ~29 tests) into `s.*` is a larger, churn-heavy follow-on, scoped separately in `design.md`; the niche seams (`now` clock, `lookPath`, `stat`-as-param, `lookup`, `isWOW64`) are out of scope.
- **Make external facts a real loader module.** Replace the `failures == nil` mode switch with an explicit unexported loader mode for CLI vs library behavior. Keep one loader implementation for directory facts, environment facts, executable facts, PowerShell facts, recursion guards, null-byte handling, blocklists, and diagnostics. Move `externalFactGOOS`/`externalFactRunCommand`/`externalFactOpen` behind a small internal loader host adapter, so tests substitute a fake loader host instead of mutating package globals.
- **Parse the config once.** Add `ParseConfig(path) (Config, error)` returning the already-complete `readConfigOptions` value (rename/export it as `Config`) with pure accessors for options, blocklist, fact-groups, and TTLs. The CLI and `Engine.Discover` each parse once and read fields; the four single-aspect `Config*` functions collapse into accessors.
- **Activate the `Formatter` seam.** Add `IncludeTypedDotted` and `Colorize` to `FormatOptions`; wire them into `BuildFormatter` (color applies only to the legacy path, machine formats ignore it, matching today). Replace the CLI's four-branch switch with one `BuildFormatter(opts).Format(facts)`.
- **Delete the dead directed-graph module.** Remove `directed_graph.go` and `directed_graph_test.go`. Verified: zero production references.
- **Remove Ruby/Puppet package-version facts.** Delete the `ruby` resolver (`resolveRubyInfo`, `rubyFacts`, `CoreFactsWithRuby`) and the puppet-agent AIO resolver (`aio_agent_version`). Stop `--puppet` from resolving `puppetversion` from the installed Puppet binary. Keep external-fact compatibility paths, including Puppet plugin `facts.d`, because those are operator-supplied external facts rather than package-version facts.
- **Non-goal — dogfooding the public `facts` facade from the CLI.** Investigated and rejected: `EngineConfig`'s CLI-only knobs (`CLICompat`, `Puppet`, `BlockedFacts`) are a deliberate, documented split (`engine.go:49-63`, ADR-0001) precisely so the public `facts` API stays small. Routing the CLI through `facts.New` would force those knobs public, fighting that decision. The facade being exercised only by its own tests is the intended shape, not a defect. No change.

## Capabilities

### New Capabilities

(none) — this is internal architecture; no new observable behavior.

### Modified Capabilities

- `go-port-supported-platform-facts`: the "Resolver fallback and diagnostic parity" requirement is **tightened**, not merely implemented. Today it requires that deterministic Go tests be injectable *through seams* — satisfied, because the pure parse functions and the `commandRunner`/`fileReader` parameters are fakeable. It does not forbid the 47 resolver calls that reach `exec`/`os` directly, outside any seam. This change adds the constraint that all host command/file access flows through the Session host seam, so every resolver is exercisable with a fake host.
- `go-port-framework-parity`: the "External fact parity" requirement is **tightened** to require one explicit external-fact loader seam for CLI and library modes. The observable input contract stays the same, but the implementation must stop encoding behavior through sentinels and package-global test hooks.
- `go-port-supported-platform-facts`: core fact parity is **amended** so `ruby` and `aio_agent_version` are absent built-ins. Facts remains compatible at the CLI/input boundary, but does not inventory the Ruby runtime or Puppet package versions.
- `go-port-framework-fidelity`: `--puppet` is **narrowed** to Puppet plugin external-fact directories and Ruby-plugin warnings. It no longer resolves `puppetversion` by executing Puppet.

Config parse-once, formatter seam activation, dead-code deletion, and the public-facade non-goal are implementation-detail refactors with no spec change. The input contract holds unchanged; the output contract intentionally drops Ruby/Puppet package-version facts, verified by updated contract/acceptance tests.

## Impact

- **Code**: `internal/engine/session.go` (host handle + `commandOutput`/`readFile`/`stat` methods), `core.go` and `virtual.go` (route the 47 direct calls through `s.*`), `external.go` (explicit external-fact loader mode + loader host adapter), `config.go` (`ParseConfig` + `Config` value), `formatter.go` (`FormatOptions` fields, `BuildFormatter` wiring), `internal/app/app.go` (parse config once, use `BuildFormatter`), `internal/engine/engine.go` (`Discover` parses config once and delegates external facts through the loader; stops appending `PuppetFacts`). Deletes `directed_graph.go` + `directed_graph_test.go`; deletes Ruby/AIO/Puppet version resolvers.
- **Tests**: the routed-through-Session calls gain fake-host coverage they could not have before (probes constructed with a fake host); external-fact tests use a fake loader host instead of mutating package globals; the existing ~29 closure-injecting tests keep working unchanged (the param threading is left in place this change); config tests assert against a parsed `Config` value; formatter tests cover `BuildFormatter` with the new options; tests assert `ruby`, `aio_agent_version`, and `puppetversion` are absent.
- **Docs**: `CHANGELOG.md` records the user-visible removal; `docs/schema/facts.yaml`, help/man text, and any affected specs drop the removed package-version facts.
- **Behavioral**: core output no longer includes `ruby` or `aio_agent_version`; `facts --puppet puppetversion` no longer synthesizes `puppetversion`. CLI formatting, config, cache, and external-fact input semantics otherwise stay unchanged.
